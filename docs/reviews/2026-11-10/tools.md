## Findings (ranked, most severe first)

### F1. Reading a view's geometry back traps the app when a program set it to a large Float
- Severity: high   Confidence: likely
- Where: `Sources/KajoApp/AppKitHost.swift:234` (`func num(_ d: CGFloat) -> ShellValue { d == d.rounded() ? .int(Int64(d)) : .double(Double(d)) }`, used by `get` for x, y, width and height at 246-253); the same `num` in `Sources/KajoApp/UIKitHost.swift:213`.
- Invariant: no primitive and no view wrapper traps on an argument a program can give (AGENTS.md's lessons "no primitive traps on an extreme SmallInteger (... two Mac shell view wrappers took any count)" and "A refusal is a value, not a trap, at a boundary that takes Smalltalk's input").
- Path that breaks it: `set` (AppKitHost 218-227) and the `frame` and `origin` ops take any `v.double` and store it in the view's frame unchanged. Any integral double outside Int64's range (1e19, 1e300, or infinity, since `inf == inf.rounded()`) passes the `d == d.rounded()` test, and `Int64(d)` then traps. From Smalltalk: `v := View new. v x: 0 y: 0 width: 1.0e20 height: 10. v width`. The same happens with `moveToX: 1.0e19 y: 0` followed by `x`. The host traps on the main thread and the app dies, a development app as well as a release app. One assumption: NSView and UIView keep a finite huge frame value as given. I did not run it. Separately, infinity or NaN given to a UIKit view raises CALayer's invalid-geometry exception already at `set` time.
- Neighbours that have it right: `TableSource.setRowCount` refuses counts past 16 777 215 instead of allocating them, and `TextOffsets.nsRange` refuses offsets out of range. The geometry setters have no such guard.
- Test that would fail today: in `ShellTests` (KajoCompilerTests), call `AppKitHost.viewCall` with `create view`, then `set width 1e20`, then `get width`. It traps today. Do the same for UIKit under `#if os(iOS)` or in the device tests mode.
- Fix sketch: in `num`, use `Int64(exactly:)` and fall back to `.double` when it answers nil. Optionally, have `set`, `frame` and `origin` refuse non-finite values or values past a bound (answer nil), so a refused value is a clean Smalltalk Error.

### F2. A reconnect resends requests that are not idempotent: retrySend and restart can run twice, proceed can hit a later stop, and a lost remove leaves stale Tonel
- Severity: high   Confidence: likely (the kernel and client code read this way; the race needs the link to drop between a request's arrival and its reply)
- Where: `tools/Client/DevClient.class.st:575-578` (`notRetried` is only `evaluate`, `process.evaluate`, `process.step`, `test.run`), `reopened` at 284-296; `kernel/Development/DevSession.class.st:316-325` (`classRemove:`), 341-349 (`methodRemove:` answers an error when the method is gone), 422-442 (`processProceed:`, `processRestart:`, `processRetrySend:`); `Sources/KajoDev/ClientHost.swift:325-331` (files are applied only from `ok: true` replies).
- Invariant: the comment on `notRetried`: "Every other request is idempotent (module 9b): a read, a compile of the same source, a command on a stopped Process that answers an error once it is no longer stopped". The project directory follows every accepted change (`docs/modules/development-protocol.md` section 3; `ProjectWriter`).
- Path that breaks it:
  1. `process.retrySend` is the define-and-retry path. The target receives it and the Process sends the message again. The send fails again (the new method has a bug) and the Process stops again at the same place, which is the common case. If the link drops before the reply arrives, the reconnect (1 s backoff) resends `process.retrySend` for the same Process id, which is stopped again, so the send runs a second time with its side effects. `process.restart` has the same shape: the restarted frame stops again and gets restarted again.
  2. `process.proceed` with a value: the Process goes on and reaches another error within the outage. The resent proceed finds a stop and proceeds through it with the value meant for the first one, so the developer never sees the second stop.
  3. `method.remove` or `class.remove`: the first run removed the method or class and its reply, which carried `files: [{path, remove: true}]` or the rewritten class file, was lost with the link. The resend answers an error ("has no method", or no such class), and `ClientHost` applies `files` only from ok replies. The project's Tonel file therefore still holds the method or class. The developer sees an error for a change that happened, `git diff` lies, and the next rebuild from the files brings the removed code back.
- Neighbours that have it right: `evaluate`, `process.evaluate`, `process.step` and `test.run` are already excluded for exactly this reason, and `method.compile` and `class.define` really are idempotent and answer their files again.
- Test that would fail today: in `tools/Tests/DevClientTest`, use `FakeDevClient` to drop the link after sending `methodRemove:` and before replying. Have the fake target answer the resend with an error, and assert that the project file was removed (or that the client did not resend). For retrySend, a fake target that counts how many retrySend requests it received for one Process across a drop asserts 1 and gets 2.
- Fix sketch: add `process.proceed`, `process.restart`, `process.retrySend`, `method.remove` and `class.remove` to `notRetried`, so they fail with "not sent again" and the debuggers refresh from `process.list` as they already do. Alternatively, make the target dedupe by (client, request id) across a reconnect and answer the first reply again, files included. That would fix every request at once.

### F3. "Objects pointing to it" and "Instances of it" evaluate the selection several times
- Severity: medium   Confidence: confirmed
- Where: `tools/Windows/DevTools.class.st:162-176` (`instancesOf:with:` evaluates `(src) instanceCount`, then `(src) allInstances: 1000`), 188-203 (`pointersTo:with:` evaluates `(src) pointerCount`, `(src) pointersTo: 1000` and `(src) printString`); `InspectorModel>>pointersToSelectedSlot` (133) for a value without a handle.
- Invariant: one action on a selection evaluates it once (Do it, Print it and Inspect it each send one `evaluate`), and the count, the list and the title must describe the same object.
- Path that breaks it: select `OrderedCollection new` (or `Foo create`, or `Smalltalk at: #X put: Object new`) in a Workspace and press ⇧⌘O. The expression runs three times. The count and the list come from two different fresh objects, the title names a third, and any side effect happens three times. With a selection that answers a different object on each run, the inspector's "N of M objects" is wrong. Instances of it on an expression that answers a different class each time mixes classes the same way.
- Neighbours that have it right: `InspectorModel>>pointersToObject` and the handle branch of `pointersToSelectedSlot` evaluate `'self'` against a handle. The object is fixed once and every request names it.
- Test that would fail today: in `DiscoverabilityTest`, use `FakeDevClient` to count the `evaluate` requests that one Objects pointing to it on a Workspace selection sends, and assert 1 evaluation of the user's source. Today it is 3.
- Fix sketch: evaluate the selection once with a result handle, then send `self pointerCount`, `self pointersTo:` and `self printString` with that handle as receiver, as the Inspector does. Subtract or name the session's handle-table holder the way the Inspector's comment already does.

### F4. `check-tier.sh` asks for nothing when a diff touches only a `.md` test fixture, and judges a rename by its new path only
- Severity: medium   Confidence: confirmed
- Where: `scripts/check-tier.sh:48` (`docs/*|*.md) print none`), 73 (`git diff --name-only`); `scripts/check-tier-test.sh` has no fixture case and no rename case.
- Invariant: AGENTS.md "Verification": a diff runs the gates of the highest tier any of its files asks for, and a change under the core directories runs all 18.
- Path that breaks it:
  1. `Tests/KajoCompilerTests/Fixtures/perf/README.golden.md`, `README.in.md` (read byte for byte by `PerfReportTests`) and `Tests/KajoCompilerTests/Fixtures/app-project/Sample/README.md` (the generator's byte-for-byte fixture) all match `*.md`. A commit that edits one of them alone exits 0 with "nothing owed: docs only", while `swift test` would fail.
  2. `git diff --name-only` lists a renamed file under its new name only, because rename detection is on by default. A commit that moves `Sources/KajoVM/Marking/X.swift` to `Sources/KajoVM/Shell/X.swift`, or out of `Sources/KajoVM` altogether, is decided as `swift`, not `core`. A staged rename in the working tree behaves the same way through `git diff --name-only HEAD`.
- Neighbours that have it right: `kernel/README.md` is caught by the earlier `kernel/*` arm. The ordering of the arms is right; the `*.md` arm is too broad.
- Test that would fail today: add `expect swift - Tests/KajoCompilerTests/Fixtures/perf/README.golden.md` to `check-tier-test.sh`. For renames, add a case that runs the git path on a scratch repository (or `--paths` fed by `git diff --name-status -M`) and expects `core`.
- Fix sketch: put `Tests/*` (or `*/Fixtures/*`) before the `*.md` arm, and limit `none` to `docs/*`, the top-level `*.md` and `experiments/*/*.md`. Collect files with `git diff --name-only --no-renames` (both sides of a rename are then listed as a delete and an add), or parse `--name-status` and classify both paths.

### F5. The matrix gates' exit status comes only from `shell-report.py --bar`
- Severity: low   Confidence: confirmed
- Where: `scripts/gates-lib.sh:66` (`matrix-mac`: `... { shell-matrix.sh ...; shell-report.py ... > report.md; shell-report.py --bar ...; }`), `scripts/device-rows.sh:72-74`.
- Invariant: "a gate reads the exit status and the error count first" (AGENTS.md).
- Path that breaks it: a `shell-matrix.sh` that dies early, or a report that throws, is ignored. The gate passes whenever the rows that exist hold no `FAILED` line and no checksum with `ok=0`. If a crash in the script itself (not in a launch) leaves no rows at all, `--bar` prints a row of zeros and exits 0, so the gate passes with no measurement. `--bar` also has no "rows expected" check.
- Neighbours that have it right: every other gate is a single command whose status is the gate's status.
- Test that would fail today: run `gl_gate matrix-mac` with `shell-matrix.sh` stubbed to `exit 1` after writing nothing. The gate logs rc=0.
- Fix sketch: `set -e` inside the brace group, or `a && b && c`. Have `--bar` exit 1 when no file has any row.

### F6. Small items
- Severity: low   Confidence: confirmed unless noted
- `Sources/KajoShellCore/Product.swift:151`: the `sudo` line quotes the CLI path with `'...'` but leaves `dir` and `link` unquoted. An app bundle under a path with an apostrophe (`/Users/x/Joni's Apps/Kajo.app`) produces a command that does not paste into a shell. Escape it as `'\''`, or quote all three.
- `Product.swift:104-115` (`CheckoutInstaller.install`): two launches of the same new version at once (two copies of the app, or a relaunch during the first copy) can interleave. Launch B finds the folder that A just completed, marker included, and moves it aside as `.incomplete-<time>` (line 112 checks `fileExists`, not the marker) before renaming its own copy into place. Nothing is lost, but a complete checkout is labelled incomplete and left behind. Check the marker before moving, or treat a failed final `moveItem` as `.present` when the marker is now there.
- `Package.swift:82-86`: the `kajo` executable target has no `.strictMemorySafety()` while every other Swift target has it. Its unsafe constructs (none today beyond `signal`) would not be flagged. AGENTS.md: "Nothing outside the core should need `unsafe`"; the flag is what makes that greppable.
- `scripts/new-check.sh:95`: the Release checks assert zero `KajoDev` and other symbols but no positive control. A stripped Release binary would pass the symbol half vacuously; the strings and `nm -u` halves still hold. Assert that a `KajoApp` or `KajoVM` symbol is present, so a zero means absent rather than stripped.
- `scripts/dist.sh:99-104`: the frameworks' compile flags are recorded in `FLAGS.txt` but never asserted. A slice built with `-Onone`, with `-enable-testing`, or whose compile line `grep -m1` did not find (empty flags) still ships. Lesson: "A product's build mode is decided by whoever builds it; read the compile line". Fail when any slice and module line lacks `-O -whole-module-optimization -strict-memory-safety` or has `-enable-testing`, `-Onone` or `-g`.
- `Sources/KajoAppDevelopment/Development.swift:67` (possible): `Host.current().localizedName` runs on the main thread in `started`. `NSHost` can block on name resolution on some networks, the same shape as the 35 s `ProcessInfo.hostName` lesson, though after the first frame. `SCDynamicStoreCopyComputerName` reads the same name without a lookup. Not measured.

## Checked and sound
- `openURL` on both hosts (`AppKitViews.swift:679`, `UIKitHost.swift:206`): `URL(string:)` with a case-sensitive scheme compare against exactly `http` and `https`. `file:`, `javascript:` and `HTTP:` are all refused (nil).
- `ProjectWriter.apply` (`Sources/KajoDev/Project.swift`): one or two components, no `..` or hidden component (a leading `.`), a class or extension suffix, a stem of letters, digits and `_`. A link in the tag's place is refused, a link at the file is replaced and never followed, and the tag directory is created non-recursively and removed only when only `.DS_Store` is left. No path escapes.
- `kajo new` and New App refusals (`Generator.swift`): the name is ASCII `[A-Z][A-Za-z0-9]{1,29}`, which rules out `/`, `..`, spaces and Unicode; reserved names and the `Kajo*` prefix are refused; the bundle id is checked as reverse DNS; the team is 10 of `[A-Z0-9]`. The checkout path must be absolute with no `"`, `'`, `\`, `$`, backtick or control character, so the YAML (double-quoted) and the build script (single-quoted) cannot be broken out of. A target directory that is a link or non-empty is refused, and files are written with `.withoutOverwriting`. xcodegen gets its arguments as an argv array (`Process.arguments`), with no shell.
- `CommandLineTool.install`: an existing `kajo` that is not a link ending in `/Contents/Helpers/kajo` is left alone (`occupied`); only the app's own link is replaced.
- `ShellRuntime`: the follow-up turn captures `[weak self]` (the 11a `unowned` trap); without a display link the frame account is renewed by the clock; a preempted or UI-only turn schedules one follow-up (`followUp` flag); the callbacks are built `nonisolated`, and the view, stuck and release hops use `MainActor.assumeIsolated` (they trap rather than race off the main thread).
- `AfterFrames` fires its body once (body niled before calling) on the N-th frame or after the bound; `startDevelopment` is guarded by `developmentStarted`.
- The token: `TokenStore` writes with `O_CREAT|O_EXCL|O_NOFOLLOW`, mode 0600, and the console line at `Development.swift:91` names the port, addresses and service name, never the token. The Mac shell's status-line token (`Pairing.swift:147`) goes to the status label; `onStatus` (which goes to stdout) is set only by the generated apps' delegates, which use the window style.
- The service name is the app name plus the device name; on iOS the device name is the model name.
- `DevClient` itself: a refused session is never reconnected; `close` while reconnecting ends at once; timers are cancelled on removal; resent requests keep their ids on the new connection; the old connection is forgotten before the reconnect, so a stray reply cannot reach the new client.
- `gates-lib.sh`: every gate runs under `gtimeout -k 60`; the fuzz gate requires the `^libFuzzer build: ok` line, and `fuzz.sh` prints it only after a successful `-sanitize=fuzzer` build; the clean build counts warnings and errors; the load loops are this script's own children only.
- `weekly.sh`: the refusal matches exact `ucomm` names outside its own process group; the summary's awk fields match `gl_log`'s format.
- `device-rows.sh`: the codesign watchdog (60 s at constant CPU time) and a 2700 s bound on the build; exit 3 when skipped.
- `canonical-tonel.sh --check`: walks one level of tag subdirectories both ways and reports a stale `.st` left at a package's root after a class moved into a tag.
- `shell-report.py --bar` knows the golden writer's every `ok` value (`Modes.swift:89-91` emits only 1, 0 and -1); `FAILED` launches are counted.
- `dist.sh` and `release.sh`: notarization only through the keychain profile name; an unsigned build is named `-unsigned-dev`; `release.sh` uploads nothing and prints the push and `gh` lines; `set -u` throughout.
- `TableSource` counts and pages, `setRowsAt` with negative or huge first rows, `TextOffsets.nsRange` bounds and scalar boundaries.
