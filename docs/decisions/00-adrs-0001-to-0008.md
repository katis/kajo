# ADRs 0001 to 0008

Decisions live in `docs/adr/`, one per file, each pointing at the experiment
that produced its evidence. Current: 0001 Swift for the VM core, 0002
repository layout, 0003 object table for object representation (accepted; 2x
per cache-missing hop and 1.8 to 2x marking against direct pointers, entry
locality rejected), 0004 Smalltalk UI code on the main thread with budgeted
preemption (proposed, built headlessly in module 3; pending a pause-bounded
collector and the shell's 120 Hz measurement), 0005 generational collection
with per-worker nurseries (proposed, built in module 4), 0006 concurrent
marking and lazy sweeping of old space (proposed, built in module 5: the
final mark is 0.11 to 0.14 ms p50 at 8 workers from 64 to 512 MiB of live
old data, the barrier costs 1.4 percent on `ivars` with marking off), 0007
age field with survivor spaces and concurrent relocation of old space
through the entry table (proposed; old-space work is off the frame budget,
scavenges remain; the age half is built in module 4, the relocation half is
model checked in `docs/models/relocation.md` and built in module 6: the
post-store check is within noise on the hot kernels in aligned builds and 5
to 10 percent on cache-missing stores, `fragment` ends at 18 MB against 240
with relocation off, zero stores redone on the hot kernels), 0008 young
collection without stopping the world, offloaded for the main thread and
local for background workers (proposed; no collector pause on the main
thread exceeds a frame, acknowledgements and the initial mark remain; model
checked in `docs/models/young-collection.md`, which found the array-copy
store ordering hole; built in module 7: the main thread's stopped time under
the allocation storm is 5 times lower than stop-the-world and comes in
acknowledgements of 28 to 44 µs, the share scenario is the one case that is
worse, and ADR 0008 raises the acceptance question for 0004 to 0008 for the
owner).
