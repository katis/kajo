# AOT 1: the native engine

AOT 1, the native engine, built 2026-11-11 to 12 (`docs/modules/aot.md`, ADR
0015 proposed; the owner's go-ahead of 2026-11-11: C as the generator's
output, Zig as the bundled compiler in module 2, no separate experiment
first): a second engine beside the interpreter, never a replacement: `kajo
aot <image or kasm files> -o <dir>` (the target `KajoAOT`, linked by the
`kajo` tool, the tests and the kasm fuzz target only) writes a header, one C
file per 150 groups, the tables and a descriptor `kajo_native_module`, and
the VM binds a compiled module at start (`VMConfig.native`,
`Headless.Options.native`, `kajo run|test --native <dylib>`,
`Sources/KajoVM/Native/`), method by method by a SHA-256 of what the
generator folded (plain bytecodes, the header counts, the primitive, each
folded literal's oop) and whole by a layout hash of every offset and
constant the C reads, a mismatch running the method interpreted and a wrong
layout or version refusing the module; native frames are the VM's frames and
a resume point is a bytecode pc with its traced depth, so the collectors,
Contexts, unwinding, stack growth, stepping, the saver and the loader see
one kind of frame and either engine continues any frame at a resume point;
sends and returns are `musttail` calls under `preserve_none`, slow paths are
C-callable wrappers over the VM's own, a driver (`drive`) above both engines
chooses at `runSlice` and `runToReturn`, the interpreter leaves for native
code only in `pollSlow` and `returnSlow`, and `interpret` is identical
instruction for instruction (1816 each in the main session's own diff of the
gate's A/B objects); returns find their caller by lookup (a marker in the
context word measured equal and is kept only for an interpreted frame a slow
path activates above a native one; the saver strips it, so no image format
change); part 3 kept inline stores restating `storeWithBarrier` and native
closure activation and did not build a per-site cache, literals bound at
bind or inline allocation; measured in aligned builds, five interleaved
runs, native against the interpreter at the same commit, at 1 worker: fib
3.43 times (58.1 to 17.0 cycles per send), `sends` 1.79, `st-sends` 4.71,
`arith` 9.76, `ivars` 4.43, `storeheavy` 3.58, `alloc` 1.36, `st-closures`
2.51, and at 8 workers 3.59, 1.72, 4.54, 10.20, 4.33, 3.70, 1.25 and 2.47;
the comparison's programs (`docs/performance/README.md` section 10, the
other runtimes not re-run) at 1 worker: fib 3.2 to 3.6 times, dispatch 1.8
(kasm) and 4.8 (Smalltalk), binarytrees 1.36 to 1.41, collections 1.84,
arith 10.6, so native arith in Smalltalk (0.76 s) is ahead of Pharo's Cog
(1.47 s) and native dispatch level with it; the kernel image's 3276 methods
